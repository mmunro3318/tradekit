- **`CLAUDE.md` "Standards" section**, lines 45-54 (~140 words / **≈185 tokens**). Deep-modules/test-doctrine/ASSUMPTIONS-protocol/commit-convention/docs-are-part-of-done are five distinct pieces of judgment doctrine restated as flat prose on every load, each already partially covered by a pipeline skill (`tk-tdd`, `tk-spec`, `tk-implement`, `tk-docs`) but not consolidated into one on-demand reference. Converting to a referenced skill (loaded when writing code / reviewing / committing, per the existing trigger pattern) would recover ~185 tokens/session.
- **`RTK.md`** (whole file via `## Tooling` → `@RTK.md`, line 56-57 of CLAUDE.md), 29 lines / ~140 words / **≈185 tokens**. Meta-command reference (`rtk gain`, `rtk discover`, `rtk proxy`) that's only actionable when the user is actively diagnosing or using rtk directly — most sessions never touch these commands. A skill triggered on "rtk", "token savings", or a failed rtk invocation would remove ~185 tokens from every other session.
- **`rules/context7.md`**, 17 lines / ~280 words / **≈370 tokens**, loaded as a standing global rule on every session regardless of whether the session ever touches a library/API question. Its own body is already a 4-step procedure (resolve → pick match → fetch → answer) — structurally it already IS a skill, just not packaged as one. This is the single highest-value conversion in the always-loaded set (~370 tokens/session, on every project, every session) because unlike the CLAUDE.md sections it has zero cross-cutting value when no library question is in play.

Combined, these four conversions remove an estimated **~860 tokens of always-loaded prose per session**, compounding across every project session on this machine (the tk-pipeline table itself, `CLAUDE.md` lines 8-34, is deliberately excluded — DESIGN.md explicitly wants that map always visible, and it's already fairly compact).
